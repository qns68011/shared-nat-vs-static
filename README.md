## 共享 NAT 与独享静态，差的是哪几样东西

把公网 IP 想成一栋公寓楼的门牌号，你分到的端口就是自己那户的门铃编号。访客只知道楼号，按对门铃，物业（转发规则）把铃声转送到你屋里真正该应门的那台设备。整栋楼共用一个地址，这就是 NAT。

它和独享静态住宅 IP 的差别，可以拆成四件事：

**IP 归属。** 独享方案里，那个 IPv4 只有你用，别人在这段 IP 上做什么都牵连不到你。共享 NAT 是一个池子，同段 IP 上还有其他人，平台风控看到的是同一个出口地址，理论上存在“连坐”的可能。丽萨主机这条线的 IP 是**静态**的，租期内不会每天换，但确实是共享的。

**端口。** 独享 IP 全端口可用，想开什么服务开什么。共享 NAT 只给你 2、4、6 或 10 个 TCP/UDP 端口，具体数量看你买哪一档。这意味着你不能随便加服务，每开一个新东西都要先算端口。

**交付方式。** 这条线不是下单即开通：付款后要提交工单，人工审核，24 小时内手动开通，登录信息通过邮件和工单给你。急单要提前安排。

**退款。** 官方页面写得很直白：“特殊产品，无退款，请购买前仔细咨询客服，谨慎购买。”同品牌的双 ISP 系列有 48 小时无条件退款，家宽 VDS 是仅退网站余额，共享 NAT 是三者里最严格的。

这四项里，真正决定你要不要多花钱的是第一项和第四项。如果你只是想“让出口 IP 显示成美国住宅”，共享 NAT 的溢价很难说得通；如果你要的是一个稳定的纽约家宽身份，并且不希望自己再去搭一台中转机，那它省掉的是麻烦，省掉麻烦要花钱。

## 端口转发怎么配：先分清“监听”和“转发”

这里有个常见误解要先纠正：NAT 机器并不意味着“没有公网入口”，它意味着公网 IP 共用、端口归你。商家已经在宿主机侧把你分到的端口映射到你的落地机上，所以**最简单的用法根本不需要配转发**：在落地机的那个端口上直接起服务就行。

只有当你需要把进来这个端口的流量再送到**另一台机器**（家里的 NAS、另一台 VPS、内网设备）时，才需要做转发。而这条产品线的落地机是 OpenVZ 虚拟化，这一点会直接影响你选哪种方案。

**方案一：本机监听（零配置）**

假设分到的是 30001 端口，装好代理或 Web 服务后让它监听 30001，外部访问“公网 IP:30001”即可。多数人到此为止就够用了。

**方案二：socat（OpenVZ 环境下最稳）**

socat 是用户态转发，不依赖内核的 IP 转发功能，在容器里几乎不会遇到权限问题，适合端口数量少的场景。

bash
sudo apt install socat -y
sudo vim /etc/systemd/system/socat-fwd.service


ini
[Unit]
Description=Socat Port Forward
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/socat TCP4-LISTEN:30001,reuseaddr,fork TCP4:目标IP:目标端口
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target


bash
sudo systemctl enable --now socat-fwd


UDP 转发把 `TCP4` 换成 `UDP4`、去掉 `fork` 即可，另建一个服务文件互不干扰。

**方案三：iptables（先确认内核转发能不能开）**

iptables 做 DNAT 需要内核开启 `ip_forward`。OpenVZ 容器共享宿主机内核，这个参数通常改不了，所以**先验证再动手**：

bash
sysctl net.ipv4.ip_forward


如果返回 0 且你 `sysctl -w net.ipv4.ip_forward=1` 时报权限错误，就别在 iptables 上继续花时间了，回到 socat。如果返回 1，可以这样配：

bash
# 把本机 30001 的 TCP 流量转到 1.2.3.4 的 8080
iptables -t nat -A PREROUTING -p tcp --dport 30001 -j DNAT --to-destination 1.2.3.4:8080
iptables -t nat -A POSTROUTING -d 1.2.3.4 -p tcp --dport 8080 -j MASQUERADE

# Debian/Ubuntu 持久化
apt install iptables-persistent -y
netfilter-persistent save


CentOS 7 用 `service iptables save` 保存规则。

**方案四：firewalld（CentOS 7 及以上）**

bash
firewall-cmd --permanent --add-port=30001/tcp
firewall-cmd --permanent --add-forward-port=port=30001:proto=tcp:toport=8080:toaddr=1.2.3.4
firewall-cmd --permanent --add-masquerade
firewall-cmd --reload


同样受 `ip_forward` 限制，先按方案三的方法验证一遍。

另外，落地机的系统是 CentOS 7 或 Debian 8，要换系统得提交工单。这两个版本都比较老，装新版软件时可能要额外处理软件源，心里有个准备。

## 常见问题

**每天换 IP 会影响我配好的转发规则吗？**

这条线的 IP 是静态的，不存在每天更换的问题，规则配好就一直有效。真正会变的是你分到的端口对应关系，那由商家侧管理，正常不会动。如果你以后换到动态换 IP 的共享 NAT 产品，规则通常仍然按端口生效，不受 IP 变化影响。

**2 个 NAT 端口够用吗？**

看用途。只跑一个代理或一个落地服务，2 个够。要同时开网页管理、代理、SSH 之外的第三个服务，就得基础版的 4 个。内网穿透场景一般需要 3 个以上，直接跳过精简版。

**能装 Windows 或者 Docker 吗？**

Windows 不行，官方只给 CentOS 7 和 Debian 8，仅 SSH 访问。Docker 在 OpenVZ 上通常跑不起来，因为需要的内核特性容器里没有。买之前先想清楚你的软件栈是不是纯用户态的。

**国内访问速度怎么样？**

回程是三网 CN2 GIA，去程三网直连，这是这条线相对普通美国 VPS 的主要优势。但物理距离改变不了：纽约比洛杉矶更远，中国到美东的往返延迟下限本身就比美西高，任何优化都只能逼近这个下限，不能突破。对延迟极敏感的业务（实时语音、竞技游戏）要有心理预期。

**支持什么付款方式，需要什么材料？**

支持支付宝和 USDT，国内用户付款没有障碍。共享 NAT 是人工审核开通，具体审核材料以工单沟通为准。

**能退款吗？**
